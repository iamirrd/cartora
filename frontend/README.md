# Cartora frontend

فروشگاه فارسی و راست‌چین کارتورا با React، JavaScript، React Router و Vite؛ متصل به API واقعی Django.

[شروع پروژه](../README.fa.md) · [راهنمای آموزشی مرحله‌به‌مرحله](docs/LEARNING.md) · [API](../docs/API.md)

## امکانات

- کاتالوگ، جست‌وجو، فیلتر دسته و برند، مرتب‌سازی و صفحه‌بندی در URL
- جزئیات محصول، گالری تصویر، انتخاب تنوع و قیمت همان تنوع
- ثبت‌نام، ورود و خروج JWT، تمدید access token و مسیرهای نیازمند ورود
- سبد خرید، تغییر تعداد، حذف، نشانی‌های ذخیره‌شده و ثبت سفارش
- مشاهدهٔ سفارش‌ها، تراکنش‌ها، پرداخت موفق یا لغوشدهٔ آزمایشی و تلاش مجدد
- علاقه‌مندی‌ها، ثبت/ویرایش/حذف نظر و پیام‌های داخل سایت
- ظاهر مناسب موبایل، فونت محلی وزیرمتن و حالت بارگذاری، خطا و لیست خالی

## اجرا

بک‌اند را طبق README اصلی روی `http://127.0.0.1:8000` اجرا کن. سپس:

```powershell
cd frontend
npm.cmd ci
npm.cmd run dev
```

Node.js نسخهٔ 22.17 یا جدیدتر لازم است. در Linux/macOS از `npm` استفاده کن؛ `npm.cmd` برای عبور از محدودیت اجرای `npm.ps1` در PowerShell است. آدرس Vite معمولاً `http://localhost:5173` است؛ اگر پورت اشغال باشد آدرس چاپ‌شده در ترمینال را باز کن.

`vite.config.js` درخواست‌های `/api/` و `/media/` را به بک‌اند می‌فرستد. برای تغییر پورت بک‌اند، مقصد پراکسی را همان‌جا تغییر بده؛ هیچ رمز یا secret بک‌اند نباید داخل کد فرانت قرار بگیرد.

## ساختار

| مسیر | مسئولیت |
| --- | --- |
| `src/main.jsx` | نقطهٔ ورود React، فونت و استایل‌ها |
| `src/App.jsx` | Providerها، چیدمان و مسیریابی |
| `src/api/client.js` | HTTP، خطاهای سرور، JWT و تمدید نشست |
| `src/components/` | هدر و اجزای مشترک رابط |
| `src/hooks/` | دریافت داده و اجرای عملیات با مدیریت وضعیت |
| `src/features/catalog/` | فهرست و جزئیات محصولات |
| `src/features/auth/` | ورود، ثبت‌نام، نشست و حساب |
| `src/features/cart/` | سبد مشترک بین هدر و صفحه |
| `src/features/addresses/` | دفترچه و فرم مشترک نشانی |
| `src/features/checkout/`, `orders/` | ثبت سفارش، پیگیری و پرداخت |
| `src/features/reviews/`, `wishlist/`, `notifications/` | قابلیت‌های حساب |
| `src/styles.css`, `src/storefront.css` | قواعد نمایش و واکنش‌گرایی |
| `tests/` | تست کلاینت، مرورگر و قرارداد API جنگو |

توضیح Props، State، Effect، Context، فرم‌ها و جریان خرید در [راهنمای یادگیری](docs/LEARNING.md) آمده است. فایل‌های `node_modules` کد کتابخانه‌ها هستند؛ برای تغییر برنامه سراغ `src` برو.

## بررسی و build

```powershell
npm.cmd test
npm.cmd run build
```

خروجی build داخل `dist/` قرار می‌گیرد و وارد Git نمی‌شود. `npm.cmd run format` کد فرانت را با Prettier مرتب می‌کند؛ قبل از اجرای آن روی فایل‌های نامرتبط، diff را بررسی کن.

## Browser tests

در ویندوز با Edge نصب‌شده:

```powershell
npm.cmd run test:e2e
```

برای Chromium روی Windows:

```powershell
npx.cmd playwright install chromium
$env:PLAYWRIGHT_CHANNEL = "chromium"
npm.cmd run test:e2e
Remove-Item Env:PLAYWRIGHT_CHANNEL
```

در Linux/macOS:

```bash
npx playwright install --with-deps chromium
PLAYWRIGHT_CHANNEL=chromium npm run test:e2e
```

در CI به‌صورت پیش‌فرض Chromium استفاده می‌شود. تست‌ها Vite را روی پورت `5175` اجرا و سپس متوقف می‌کنند؛ این پورت باید آزاد باشد. پاسخ API کنترل‌شده است؛ تست‌ها به بک‌اند یا دیتابیس شخصی نیاز ندارند. گزارش شکست و trace داخل `test-results/` نگهداری می‌شود و در Git قرار نمی‌گیرد.

## نکته‌های اتصال واقعی

- محصول، دسته و برند برای نمایش عمومی باید فعال باشند. برای خرید، تنوع و موجودی فعال هم لازم است.
- بعد از ساخت یا تغییر محصول در admin، صفحهٔ فروشگاه را رفرش کن؛ همگام‌سازی زنده با ادمین پیاده نشده است.
- قیمت‌ها بدون تبدیل واحد پول نمایش داده می‌شوند؛ مبلغ نهایی و اعتبار موجودی را سرور تعیین می‌کند.
- ثبت سفارش سبد را خالی می‌کند. اگر پرداخت ناموفق شد، از همان سفارش در «سفارش‌های من» ادامه بده.
- پرداخت به `DJANGO_DEBUG=True` و `ENABLE_MOCK_PAYMENTS=True` نیاز دارد و پول واقعی جابه‌جا نمی‌کند.
- ورود فروشگاه JWT است؛ ورود `/accounts/login/` روی بک‌اند session است و برای admin کاربرد دارد. ورود در یکی، دیگری را وارد نمی‌کند.
- نشست فروشگاه در حافظه و `sessionStorage` همین تب نگه داشته می‌شود؛ refresh آن را حفظ می‌کند. این نسخه از HttpOnly cookie برای JWT استفاده نمی‌کند.
- مدیریت کالاها در Django admin انجام می‌شود. ویرایش پروفایل، بازیابی رمز React، ورود اجتماعی React و Push مرورگر پیاده نشده‌اند.

## استقرار

این پروژه با GitHub Pages به‌تنهایی یک فروشگاه متصل به بک‌اند نمی‌شود. خروجی فرانت باید روی میزبانی قرار بگیرد که مسیرهای React را با fallback به `index.html` سرو کند و `/api/` و `/media/` را به مقصد درست بفرستد. پراکسی Vite مخصوص dev است؛ `vite preview` جای تنظیمات وب‌سرور را نمی‌گیرد. جزئیات و محدودیت‌ها در [راهنمای توسعه](../docs/DEVELOPMENT.md) آمده است.
